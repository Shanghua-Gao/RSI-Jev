# RSI-Jev v4.0-VL

*Describes release v4.0-VL · updated 2026-09-30*

**RSI-Jev now reads images.** Send one to four pictures with a request — a photo, a
screenshot, a scanned page, a chart — and ask typed questions about them: yes/no,
pick-one-of-*k*, rate-on-a-rubric. As before, one forward pass returns a calibrated
probability for every option, with no generated text. Text requests work exactly as they
did.

On five image benchmarks held out from training it answers 80.3% of questions correctly;
with the images blanked out it drops to 45.8%, so the answers come from the pictures. On
text it keeps v3.0's level: 0.756 on the fifteen-benchmark suite, 0.653 on the held-out set.

v4.0-VL is v3.0's lineage with three rounds of image training, a calibration data round, and
a new RL stage on top. It is a 2B model, one seed.

---

## 1. The task

Unchanged from [v1.0](v1.0.md#1-the-task), plus images: a document (the *state*), now
optionally with 1–4 images placed in it by `<image>` markers, and one or more typed questions
— `noul`, `choice`, `score` — with a probability per option, returned in one forward pass.
**Top-1** is the fraction of decisions whose highest-probability option matches the label;
**ECE** is expected calibration error, the average gap between the confidence a model reports
and how often it is right at that confidence, lower being better.

## 2. How the model is built and trained

Qwen3.5-2B-Base, with v1.0's option scorer, v2.0's confidence head and v3.0's MLP readout.
Images go through the base model's own vision tower, **frozen**: its weights are not in this
checkpoint and are loaded from `Qwen/Qwen3.5-2B-Base`. Every request gets at most 1,024 image
tokens per question, split evenly across its images.

The stages, each continued from the one before:

1. **Text, supervised.** v3.0's data-scale-2 corpus with the Jev-Style sources capped at 3,000
   questions each, 14,233 steps.
2. **Images, supervised, 4,000 steps.** 33,906 image questions from the train splits of twelve
   public datasets (DocVQA, ChartQA, VQAv2, A-OKVQA, NLVR2, Hateful Memes, Screen2Words, AI2D,
   ScienceQA, TallyQA, RVL-CDIP, TQA), mixed with 30,094 questions of text replay. Free-form
   answers became four-way choices with real distractors, or balanced yes/no questions.
3. **v3.0's listwise reranking RL stage**, run on the image model.
4. **Images, second round, 3,000 steps.** 17,352 new image questions — more public VQA train
   sets and six synthetic generators (UI state, change detection, line rules, grid games and
   others) — with 51% text replay.
5. **Calibration data, 3,000 steps.** 8,492 generated reasoning questions (lie chains, object
   swaps, orderings) at depths where the model is at chance, trained toward soft targets so it
   learns to say so. These share task families with BIG-Bench Hard; see
   [§4.1](#41-the-held-out-comparison--read-this-first).
6. **An asymmetric RL stage, 1,500 steps.** The reward is correctness minus a confidence
   penalty that charges a confident mistake four times what it charges a timid correct answer:
   `R = c − 4·max(0, p − c)² − 1·max(0, c − p)²`, with `p` the probability on the chosen option
   and `c` whether it was right. 30% of its rows carry images. It calibrates in the weights:
   held-out ECE before any calibration falls from 0.200 to 0.082.

**Against a matched supervised stage** — the same data, steps and seed, with only the
objective changed — the asym stage gave better held-out accuracy and calibration, with no detectable
ranking difference (one seed):

| both after the same calibrator selection | asym stage (**v4.0-VL**) | matched supervised stage |
|---|---|---|
| held-out, pooled top-1 | **0.6528** | 0.6442 |
| held-out without BIG-Bench Hard, top-1 | **0.703** | 0.694 |
| held-out ECE | **0.0822** | 0.0871 |
| suite ECE | **0.043** | 0.055 |
| MMLU-Pro 1k | **0.385** | 0.375 |
| images, held-out top-1 | 0.803 | 0.804 |
| held-out without BIG-Bench Hard, AUROC | 0.6935 | 0.7017 |

The AUROC gap is −0.008 with a paired bootstrap standard error of 0.006.

**Calibration.** The confidence head (`oof_head_scorefloor`, as in v2.0–v3.0) is refitted on
8,464 held-out questions: one in ten of the text corpus, plus 1,251 image questions weighted
0.15. Cases whose document or image also appears in a trained case were dropped first. It
rescales each question's probabilities without changing which option wins.

## 5. Speed, the wire format, and what `confidence` means

Text inference is unchanged: one tower pass per question, the calibration a division inside
the readout, nothing generated.

**Images** ([`../serve/README.md`](../serve/README.md#images) has the limits):

- A request carries `"images": ["data:image/png;base64,…"]` beside `state`: 1–4 PNG, JPEG or
  WebP data URLs. The state marks where each goes with `<image>`; without markers the images
  go first. URLs are not fetched.
- The vision tower runs once per request, and the state with its image tokens is read once for
  all the questions. With `--profile agent`, a repeated image state is not read again.
- Up to 1,024 image tokens per question (about one megapixel for a single image, 256 tokens
  each for four) on top of the 2,048 text tokens.
- On the GB10, one 640 px photo takes 80 ms with one question and 110 ms with four; a
  1,600 px photo, 245 ms and 273 ms. Asking again about the same image under `--profile agent`
  takes 36–101 ms. [`../docs/inference.md`](../docs/inference.md#images) has the table.
- Image requests need Pillow and torchvision: `pip install "rsi-jev[vision]"`. Without them the
  server still starts and answers text; an image request gets a 422 saying what to install.

A structured criterion (an object rather than a string) is still rejected with 422, and a
document longer than **2,048 tokens is cut from its start**. With images, a request whose cut
would reach an image is refused rather than cut.

The API returns a probability *and* a `confidence`, and they are different numbers: `confidence`
is the peak statistic Jev documents, `(K * p_max - 1) / (K - 1)`. Route on the probability of the
option you intend to act on.

## 6. Limitations

- **Images are capped at four per request and 1,024 tokens per question.** A large photo is
  scaled down to fit, so small text in a full-page scan can be lost.
- **Image requests are slower than text**: an image adds hundreds of tokens, and a large photo
  up to 1,024 ([§5](#5-speed-the-wire-format-and-what-confidence-means)).
- **The vision tower is the base model's, unchanged.** Everything this release learned about
  images is in the text tower and the scorer.
- **BIG-Bench Hard is not held out for this release** ([§4.1](#41-the-held-out-comparison--read-this-first)).
- **The weaknesses external testing found in v2.1 are still here**: a lean toward the more
  severe option on ordered choices, rarely choosing "unknown" when a question cannot be answered
  from the document, and inconsistent answers to a question and its negation. Do not use it where
  an "unknown" option has to be honoured without checking it on your own data.
- **The recipe cannot yet be rerun from this repo.** The asymmetric RL objective, the image
  training feed, the image corpus builders and the calibration fit with an image holdout are
  not published yet. The checkpoint, its loader and the serving code are.
- **Documents over 2,048 tokens lose their beginning** ([§5](#5-speed-the-wire-format-and-what-confidence-means)).
- **One model, one size, one seed.** The comparison with the matched supervised stage is one
  seed too.

## 7. How it got here

| step | arm | what it established |
|---|---|---|
| base | v3.0's stage-1 corpus (`v4-rep-b-s17ck`) | the text starting point |
| images | `vis-ct-1` | the model reads images: held-out image top-1 0.809 against 0.796 for its text-only control |
| RL | `rl5-listwise-vis` | v3.0's listwise reranking stage, on the image model |
| images | `vis-ct-3` | a second image round with synthetic generators |
| calibration data | `calA-ce` | generated reasoning questions with soft targets |
| RL | `asym-calA` | the asymmetric stage: held-out ECE before calibration 0.200 → 0.082. **This checkpoint**, with the confidence head refit |

Rejected along the way: a second image data portfolio that raised its own probes but not the
held-out image set (−0.006), and training the calibration round on true answers instead of soft
targets (it learned the reasoning families and failed held-out calibration). The full record is
[`../EXPLORE.md`](../EXPLORE.md).
