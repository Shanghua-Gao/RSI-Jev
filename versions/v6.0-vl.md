# RSI-Jev v6.0-VL 5B

*Describes release v6.0-VL · updated 2026-10-05*

**Each question picks its own depth.** v6.0-VL reads a decision at three depths of one
model — after layer 16, 20 and 32 of Qwen3.5-4B-Base — and answers at the first one that is
confident enough. Easy questions stop early; hard ones go to the last layer. It takes the same typed
questions as before — yes/no, pick-one-of-*k*, rate-on-a-rubric, about text and up to four images —
and returns a calibrated probability for every option, plus the depth it answered at.

v6.0-VL is a System One model: one forward pass, no generated reasoning, a probability for every option. `effort` sets how many layers that one pass uses (16, 20 or 32), not how many tokens it writes; it writes none.

It is a 5B model: **4.69B parameters** — the 32 decoder layers (3.57B),
the token embeddings (0.64B), the vision tower (0.33B), the main decision head
(0.05B) and the two early-exit heads (0.10B). The checkpoint is self-contained.

Checkpoint: [shgao/rsi-jev-v6.0-vl-5b](https://huggingface.co/shgao/rsi-jev-v6.0-vl-5b) · this record: `versions/v6.0-vl.md`

## 1. The task

Unchanged from v5.0-VL: a state (text, optionally images), one or more typed questions, a
probability for every option in one forward pass. New in the response: `usage.depth`, the layer each
question was answered at.

## 2. How the model is built and trained

Full fine-tuning throughout (no LoRA), from `Qwen/Qwen3.5-4B-Base`, seed 17 unless noted, own-token option readout.

1. **Trunk, main head and early-exit heads, 10,000 steps** (batch 16 × 8 accumulation). A text corpus of 148 sources
   (453k training rows) with duplicates, label clashes and class-skewed sources removed. The early-exit heads at
   layers 12, 16 and 20 read a detached copy of their layer, so no gradient from them reaches the shared layers;
   the bottom 8 layers train at a tenth of the learning rate.
2. **Early-exit heads refit, 3,000 steps**, trunk and main head frozen, same corpus.
3. **Images, 3,000 steps** (batch 16 × 8): new image and text questions plus replay, 48,000 questions.
4. **All four decision heads retrained under the own-token readout, 600 steps** (batch 8, lr 1e-5, seed 1, trunk frozen).
5. **Per-exit temperatures** fitted on a held-out development set (no training), and **the exit policy** selected on it (below).
   The layer-12 exit lost to the cascade from 16 in every comparison and is not in the package.

Two findings shaped the recipe: retuning heads on a trunk trained with attached early exits did not recover the
deep layers' accuracy, so the early exits are detached; and 10,000 steps on the cleaned corpus beat 40,000 on the
older one on the held-out set (+0.026) and MMLU-Pro (+0.043).

**Exits.** Decision heads read layers 16 and 20 as well as the last layer (32). Each exit has
its own scalar temperature, fitted on held-out DEV rows (T = 1.88 at layer 16, 1.97 at layer 20, 2.23 at layer 32).

**Choosing the exit.** With `auto`, a question answers at the first exit whose calibrated top probability
reaches that exit's threshold, 0.95 at layer 16 and 0.59 at layer 20, else at layer 32. With no effort set, one
threshold, τ = 0.59, applies at both exits (multi-question requests). The thresholds were picked on one half of a held-out development set weighted like our test suite and confirmed on the other half, then read once on test; nothing was tuned on test or Decision Index rows.
Mean depth on the suite: 23.3 with `auto` (20.9 with the single threshold).

## 4. Results

### 4.1 Against v5.0-VL

Four ways to run the same weights, set per server (`--effort`) or per request (`"effort"` in the body): `low` stops at layer 16, `medium` at 20, `high` at 32, and `auto` answers at the first exit that is confident enough, with its own threshold at each exit (0.95 at layer 16, 0.59 at layer 20). With no effort set, single questions run at layer 32 and multi-question requests use a cascade with one threshold, 0.59, at both exits. Images always run all 32 layers. Suite is the fifteen-benchmark mean **without `open_jev_ood`** (see §8).

**Which tasks need which depth** (Decision Index sample, skill by exit; differences under 0.03 are noise):

- Done by layer 16: function calling (BFCL), intent (CLINC150, BANKING77), When2Call, sentiment (FinEntity), phishing, retrieval (BRIGHT, Amazon ESCI).
- Need about 20: commonsense and inference (HellaSwag, ANLI, BBH, NLI4CT), claim verification (HoVer), causal reasoning (CLadder), stance (VAST).
- Keep improving to 32: GPQA Diamond (0.136 / 0.177 / 0.218), multi-step reasoning (MuSR), code execution (CRUXEval), tool documentation (API-Bank), music (POP909).
- A few simple classification tasks get worse with depth: BANKING77 (−0.035), New Yorker caption matching (−0.060), Amazon ESCI (−0.037).

### 4.3 Calibration

Each exit has its own scalar temperature, fitted so that confidence matches accuracy at that exit: final-set ECE after calibration 0.036 as served by default, 0.024 with `auto` (v5.0-VL: 0.042).

## 5. Speed and serving

Median latency per request on the Decision Index sample, one NVIDIA H200, bf16:

| default | auto | low (16) | medium (20) | high (32) |
|---|---|---|---|---|
| 40 ms | [PLACEHOLDER] | 23 ms | 27 ms | 40 ms |

`medium` matches `high` on the Decision Index at about 70% of the latency; `low` takes 57%.

Inputs up to 32,768 tokens, nothing cut (longer gets a 422); up to 5,120 options.

The API returns a probability *and* a `confidence`, and they are different numbers: `confidence`
is the peak statistic Jev documents, `(K * p_max - 1) / (K - 1)`. Route on the probability of the
option you intend to act on. The response also carries `usage.depth`, the layer each question was
answered at.

## 6. Limitations

- One seed for the head stage, as for v5.0-VL.
- The early exits read text only; questions with images always run all 32 layers.
- `auto`'s thresholds were chosen on our development sets; on workloads unlike them, check `usage.depth` and `usage.confidence` in the responses, or set an effort.

## 7. How it got here

95 arms ran on this line: one per distinct experiment id with a run record, first recorded on or after
2026-10-03 (the v5.0-VL release day), a rerun counted once; 91 if the four data audits are left out. This window
is counted by a different rule than the earlier sections, so the totals are not strictly comparable.

- **Depth was lost in training, not in the head.** On the first multi-exit model, retuned heads on the frozen trunk
  still left layer 32 below layer 20 on MMLU-Pro. Detaching the early-exit heads from the trunk gave a model that is
  no worse at layer 20 and better at 32.
- **Shorter, cleaner training beat longer training on held-out data.** 10,000 steps on the cleaned corpus beat
  40,000 on the older one on the held-out set (+0.026) and MMLU-Pro (+0.043), and lost only on the in-distribution
  suite. Dropping rows because they were easy lost at equal steps; dropping only bad and class-skewed rows did not.
- **The exit policy has to be fitted on data that looks like the test mix.** Cascades tuned on in-distribution
  held-out rows stopped too early on hard questions. A development set of held-out proxies weighted like the
  evaluation mix, with one temperature per exit, passed every release bar.

The full list of arms on the released line is in [`EXPLORE.md`](../EXPLORE.md).

Not yet: the training code for the detached early exits (stage 1), the head refit (stage 2) and the exit-policy

## 8. Corrections to v5.0-VL's record

The v5.0-VL record is left as published; these are its errata.

- §4.3 "all 150,512 requests answered": that run was 150,759 requests, all answered (150,512 was an
  earlier test run's count). The index, 38.38, is unchanged.
- A contamination audit after release found about 1,000 items of the Decision Index kit's test rows
  in the training corpora (ANLI 274, RouterBench-GSM8K 90, ARC 5, and BRIGHT/ToolRet query text
  without labels: about 0.3% of the kit's rows). Re-scored without them, the index moves by at most
  0.04 on our sample. The internal suite task `open_jev_ood` overlapped 579 training rows, so the
  15-benchmark suite (0.764) is inflated by an unknown amount; from this release the suite is
  reported with and without it. MMLU-Pro, BBH and the held-out final set have no overlap.
